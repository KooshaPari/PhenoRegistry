# Canonical design and complete artifact traceability

Source: INT-006. This is a proposed implementation contract, not a live engine state.

## PROOF-15-01 — Editable design source
Persist inspectable design/mockup/flow sources with versioned previews.

Acceptance: A runtime screenshot cannot replace the missing editable design when required.

## PROOF-15-02 — Variant state coverage
Design relevant empty/loading/error/permission/recovery and support variants.

Acceptance: One happy-path frame cannot close an entire flow.

## PROOF-15-03 — Approval fidelity
Separate exploratory, proposed, reviewed and accepted design versions.

Acceptance: An agent-written approved field without actual decision evidence does not promote scope.

## PROOF-15-04 — Baseline separation
Distinguish intended design, regression baseline and actual implementation evidence.

Acceptance: Autoupdating a failed screenshot baseline without a decision cannot close the defect.

## PROOF-15-05 — Full artifact accountability
Classify meaningful code/config/assets/docs/tests/builds/research/runtime evidence and lineage.

Acceptance: Excluded code or generated files do not disappear from the inventory without producer/scope rationale.

## PROOF-15-06 — Bidirectional trace
Find unimplemented intent and undocumented/orphan implementation with typed relations.

Acceptance: A complete forward link set does not conceal an unowned public command.

## PROOF-15-07 — State and ownership
Retain authority-specific source/state and machine-readable reconciled projections.

Acceptance: A generated page does not fabricate an AgilePlus engine transition or authoritative data move.

## PROOF-15-08 — Scope evolution
Preserve full horizon and bounded CVP, with explicit requirement/scope version changes.

Acceptance: Dropping a hard requirement to improve the percentage is visible and needs authorization.
