# One existing chat per repository — current execution contract

**Effective for this package: September 16, 2026.** The user states one chat is already open for every non-zz repository. This replaces the earlier ten-chat Tracera and paired-product allocation. It does not claim those sessions were inspected and does not authorize new cross-repository writes, merges, archival, deletion, publication, DNS or policy changes.

## One owner, several responsibilities

The existing chat owns the parent outcome: delta atlas, intent/spec reconciliation, meaningful independent assurance, current SOTA/pilot, consumer-aware simplification, and a role-specific installed/deployed CVP or accepted library/custody outcome. These are workstreams, not a requirement to spawn additional permanent chats. Tracera's ten technical concerns remain relevant but are now organized under its one owner.

The owner may use available authorized tools or isolated subagents under its actual harness policy; do not assume they exist or let delegation expand permissions. Different phases or subagents of one owner do not automatically count as independent approval. Use objective negative oracles and the actual designated reviewer/peer/coordinator for independent acceptance. No reviewer assignment or approval is manufactured in this package.

## Delta, not restart

Read the current repository instructions and accepted task. Bind immutable repository ID, default branch, actual worktree, dirty state, current artifact, existing PRs, reviewers and true engine state. Reuse fresh valid work. A report added to Git does not prove this ZIP was read, and an open chat is not proof of current execution.

Return the compact worker receipt in your subject folder. Refresh source/config/build/installed identities separately. If no remote movement is visible, inspect local work and branch state before concluding inactivity. A stale or missing source is unknown until resolved.

## Ecosystem first

Prefer reuse, modification, adaptation and narrow wrapping of suitable mature external or owned capabilities over a new handroll. Improve the authoritative shared implementation when that lowers overall burden. Never copy a sibling implementation just to gain local control. Distinguish current, committed-future and plausible-future consumers; preserve real contracts and keep speculative extension points economical.

Repository ownership constrains writes, not reasoning. Send linked consumer/source change requests to other owners, including PhenoShared. For a coordinated change, name one integration lead and record source-target-consumer versions, compatibility evidence, current adoption and rollback. Do not force every product to import the whole foundation or synchronize releases unnecessarily.

## Assurance and actual finish line

Retain independent unit, integration, E2E and other applicable accepted floors of at least 85%, with stricter accepted thresholds and complete critical obligations. Required missing, skipped, mocked or unsupported results do not pass. Qualify the checker with negative controls; compiling an included subset is not whole-product acceptance.

Document hypotheses, actual source facts, author-reported results, observed native/hosted results and unknowns separately. A safe offline placeholder can qualify a pipeline rehearsal but not the real product it stands in for. Explain missing behavioral proof instead of assigning an unsupported score.

Keep task, PR, integration, test-qualified artifact, published artifact and installed/adopted outcome separate. Inherited in-repository problems remain the parent's work even when they belong in a separate PR. A true external blocker names owner, exact action and wakeup condition. The owner can release its execution slot when blocked without marking the parent complete.

## Scope and safety

This package changes dispatch documentation only. It does not grant implementation permissions beyond the already accepted assignment. No admin merge bypass, force-push, branch purge, repository deletion or unreviewed retirement. Preserve dirty/untracked state, history, custody, private captures and licenses. Keep external/fork network repositories under the existing no-delete default. Reconcile uncertain mutation outcomes before retries.

Protect foreground gaming/audio and other user work through global CPU/GPU/RAM/I/O and session admission. Twenty-four chats are not twenty-four simultaneous expensive native tests. Fix useful bounded failures without starting another portfolio-wide architecture rewrite.

AgilePlus and PhenoDocs remain tools, not hardcoded portfolio registries. Query actual engine state when needed, rather than inferring transitions from files. SROC/CDP remain unresolved terms; do not invent expansions. Current repo/source-native systems and richer records are preserved and adapted.
