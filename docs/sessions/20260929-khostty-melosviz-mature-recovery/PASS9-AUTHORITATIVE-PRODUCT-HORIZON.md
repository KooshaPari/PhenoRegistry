# Pass 9 — authoritative product horizon correction

Observed 2026-09-30. This pass records explicit current user intent and corrects recovery decisions that had become too narrow.

## Melosviz

**Authoritative identity:** audio-conditioned programmable **multi-scene** visual composition/generation system. Given audio plus configuration/programming/creative controls, produce a unique temporally and semantically aligned sequence of scenes suitable for music-video/YouTube visualization, short form, other long form and—where qualified—real-time/live audience contexts.

The product unit is the composition/session, not an isolated scene. Scene generation/rendering is a constituent capability. Heterogeneous scenes and cross-scene ordering/timing/transition/coherence are central.

Consequences:
- multi-scene is normative, not merely an adversarial fixture;
- M-F13/M-F16/M-F18 are critical-spine failures;
- a single-scene demo cannot qualify the product CVP;
- offline and live are projections over shared audio/timeline/scene intent, with different execution guarantees;
- exact historical hybrid scanner/photo/mesh/splat implementations remain to reconcile, but the broader multi-scene composition intent is no longer authority-ambiguous.

## Khostty

**Authoritative identity:** intentional Ghostty fork spanning Windows support, deeper Zsh/PowerShell/platform support and a deep programmable socket/API control plane, conceptually near cmux-class terminal/workspace programmability. It is intended as precursor/infrastructure for HeliosLab so agents/users can manipulate terminal resources directly instead of relying on AppleScript/UI automation.

Consequences:
- a substantial fork is accepted product intent; existence research should optimize it, not repeatedly ask whether the control plane belongs;
- upstream/Ghoztty/WezTerm/cmux remain subsystem bootstrap/design comparisons;
- the currently unmounted JSON control server is a core implementation gap, not merely speculative code;
- Windows and shell integration are first-class capabilities;
- mature ontology includes instance/workspace/window/tab/pane/terminal/process identities, commands/queries/events, policy, human UX and HeliosLab consumers.

Current external documentation reinforces useful design priors: cmux exposes programmable workspace/screen/pane/terminal resources with CLI/socket APIs and idempotency semantics; WezTerm exposes pane IDs, workspaces/domains, pane input and screen introspection; upstream Ghostty has substantial Zsh shell integration but does not make PowerShell an equivalent shell-integration target in the inspected docs. These comparisons guide Khostty design; they do not negate its accepted identity.
