## Reopen rule

Do not reopen or expand the non-execution contract for ordinary implementation work.

Reopen only if at least one occurs:
1. new direct user intent changes product identity/scope;
2. contradictory source/history evidence survives authority review;
3. a previously unknown state-owner/domain/actor/lifecycle class is discovered that the ontology cannot explain;
4. fresh adversarial review produces an unexplained valid counterexample;
5. materially changed SOTA falsifies a build/bootstrap/existence decision.

Execution failure normally updates implementation/evidence mapping and may falsify an architecture decision; it does not justify generic requirement-document growth.
