# ADR-014 — Reciprocal perspectives over capability federation

**Status: proposed. Source: INT-005.** No human acceptance or engine transition is claimed.

## Context

The previous applet model describes recursive components but does not require co-install discovery, host-relative native integration or safe lifecycle. The user wants either installed app to feel primary while useful peer capabilities appear integral, with an optional App Center and open robust mechanisms.

## Decision proposal

Separate package installation, capability binding, service instance, UI perspective and data authority. Use typed offers/requirements and versioned recipes to compile scoped composition plans. Co-install discovery can enable previously authorized safe integrations; it never creates blanket trust. Preserve independent app value and select native/host-native contributions before lower-fidelity remoting. Composite applets expose intentional reduced contracts. Data/work authorities do not change when the primary perspective changes.

## Alternatives

A launcher with deep links is the cheapest useful baseline but does not achieve the full experience. A mandatory central super-app produces a stronger single shell at the cost of independence and a wider failure domain. Pair-specific ad hoc integrations may be economical for very few pairs but do not replace shared contracts where multiple consumers exist. A universal UI/runtime rewrite has no demonstrated necessity. OSGi/Felix, native extension frameworks, Theia/VS Code, Module Federation and WIT each solve parts, with different runtime and security costs.

## Consequences

Host adapters, lifecycle tests and contract versioning become real engineering obligations. Some native providers require restart, some integrations remain lower-tier, and some apps legitimately supply no GUI. The full product cannot claim to merge arbitrary third-party software automatically. Shared packages belong in existing appropriate owners, not a new repo by reflex. Current owner chats and separate review authority remain.

## Reconsideration

Prefer simpler handoff if the pilot shows no meaningful workflow benefit. Choose an existing richer shell when adaptation is cheaper than a custom one. Change broker topology when failure/resource evidence demands it. Do not expand permission or merge data merely to make an experience demo smoother. See the [full contract](../federation/README.md).
