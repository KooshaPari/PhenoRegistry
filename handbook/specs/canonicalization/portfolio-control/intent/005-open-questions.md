# Portfolio-level open questions

These are not requests for immediate clarification. They are evidence and decision targets.

## Authority

- Should RepoLedger own live repository observations while phenotype-registry owns curated roles?
- Should PhenoSpecs remain cross-ecosystem contracts only, or does it have another durable role?
- Where should active policy enforcement live?
- What is the current canonical AGSLAG/portfolio allocator home?
- Is Tracera the relationship/evidence authority while specialized ledgers own their source facts?

## Public portfolio

- Which 10–20 names should users actually remember?
- Which forks should remain public and how should they be labeled?
- Which products are career/portfolio proof versus intended maintained offerings?
- Which private products need a public projection rather than a duplicate public code repo?

## Execution and agents

- Does Agentora/agentkit have independent consumers and a validated SDK advantage?
- Where does substrate end and thegent begin?
- Which ShareCLI features are generic process/runtime value versus agent-specific integration?
- Do HeliosLab, forgecode and helios-cli maintain distinct jobs after shared framework extraction?

## Foundations

- Which small packages have at least two real consumers?
- Which generic repos hide distinct lifecycle boundaries?
- Which “Kit” repos should be package workspaces versus standalone SDKs?
- Which shared dependencies cause cross-repo path coupling or synchronized releases?

## Routing/MCP

- Which router is the product, which are upstream forks, and which are compatibility adapters?
- Is there one canonical monitoring/observability home?
- How should framework, server collection, router and app-specific MCP layers be separated?

## Compute/fabric

- Should the distributed compute/data/I-O fabric be a new independent runtime product?
- Which responsibilities remain in ShareCLI, hwLedger, nanovms, fleet ops and future fabric packages?
- What same-host, LAN and WAN prototypes are required before repo boundaries are fixed?

## Applied products

- Which applied products have independent users/jobs and deserve long-term support?
- Which families share engines or content pipelines without sharing product identity?
- Which historical apps contain recoverable capabilities versus obsolete experiments?

## Migration

- What Git history technique is appropriate for each absorption/split?
- Which package names, URLs, releases, issues and consumers must remain compatible?
- Which archives can remain raw-count-only without operator burden?
- What is the acceptable temporary bridge duration?

## Operations

- What is the maximum active incubator count?
- What are the human review and CI/hardware bottlenecks?
- What data should the operator dashboard show by default?
- Which closure throughput is realistic after the first measured wave?
