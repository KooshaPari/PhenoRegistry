# INT-001 synthesis: formal portfolio mandate

## Human objectives extracted

The user wants a complete, evidence-grounded operating model for a 146-repository portfolio that can be delegated to local agents without losing cross-repository coherence.

The requested outcomes are:

1. Evaluate every owned repository, including forks, private repositories and archives.
2. Determine whether each repository’s purpose and intended product are recoverable and complete.
3. Complete everything that can be defined before implementation: intent, SOTA, research, product contract, specifications, architecture, ADRs, plans and artifacts.
4. Build a machine-verifiable red quality envelope for every applicable aspect.
5. Complete implementation to green only after the contracts and oracles exist.
6. Require empirical pilots/case studies for independently positioned products and frameworks.
7. Reconcile duplicated, generic, tiny, forked, archived and semantically overlapping repositories.
8. Reduce the operator’s and agents’ daily portfolio width without creating unmanageably deep repositories.
9. Permit focused standalone incubation, but require eventual graduation, absorption or archive.
10. Preserve a semantic product philosophy across otherwise independent applied products.
11. Work closure-first: finish useful vertical slices and terminal repository dispositions rather than partially improving everything.
12. Respect superior existing local intent/docs/evidence systems.
13. Produce a current map, target map and dependency-ordered transition program.
14. Make the program self-contained enough for local agents while retaining central adjudication.

## Formalized mandate

> Build a capability-first portfolio control system that can explain, verify, compare, operate and govern every material product and component; partition that capability graph into an optimal polyrepo topology; and drive bounded repositories/families to evidence-backed terminal states through a closure-first work program.

## Corrections applied

### Repo count

The target is not a single raw number. Operational, authority, product-brand, incubator, fork and archive counts are separated.

### Microrepo assumption

Focused development does not automatically require permanent repository independence. Worktrees, packages and incubator repos can provide focus; permanence needs lifecycle evidence.

### Universal parity

Absolute superiority on every possible dimension is replaced with critical parity floors, explicit tradeoffs and a must-win wedge/distinct job.

### Complete representation

Every concern is trace-linked across applicable layers rather than manually duplicated in all layers.

### “All competitors”

The search is bounded and classifies direct competitors, alternatives, primitives and workflows. Counts are not padded.

### Parallelism

One agent per repository at once would create more conflicting SSOTs. Central schemas and authority precede broad delegation; WIP is limited.

### Agent-completion claims

Recent, large or richly documented work is not presumed correct. Negative controls, release artifacts, historical evidence and independent review are required.

## Non-negotiables

- All 146 repos receive census and disposition coverage.
- Archives remain lineage inputs.
- Current GitHub state is not enough when history triggers fire.
- Better local prompt/provenance systems survive.
- Cross-repo authority decisions remain centralized.
- User-facing product claims need evidence.
- Foundations/forks can be strategically justified without fake novelty.
- Migrations preserve history, attribution, consumers and rollback.
- Work proceeds in closure units.
- Unknowns remain visible.
