# Reusable master file set

The master template is this file set plus the retained versioned catalog, profiles and schemas—not a thousand-row Markdown table.

## Included blank dossier

`blank-assessment/` is a deliberately unaccepted TEMPLATE instance with a small 12-criterion discovery selection, unresolved applicability, no observations, no qualification, and no maturity claim. Its subject descriptor is explicitly a template, not a real source snapshot.

Copy it to the current subject owner's audit path, outside the immutable distribution. Replace the actual context, subject/BOM, mandate, intent, applicability, selection, gates, and measurement bindings before using it operationally. Do not flip TEMPLATE to OPERATIONAL without resolving the required source values and evidence. Recompute assignment locks through your controlled writer whenever canonical assignment bytes change.

## Other templates and schemas

Use `../core-v1.0/templates/` for individual intent, mandate, genesis, evidence-related workflow, findings, decisions, work items, checkpoint, amendment and transport records. Use `../core-v1.0/schemas/` for their exact core 1.0 shapes. `../schemas/dossier.schema.json` is the additive 1.1 context schema.

YAML is provided as a generated view here. Human authoring YAML is a future optional intake path; it must compile into canonical locked JSON rather than becoming a competing live authority.

## Three depth modes

- **Screen:** a bounded inventory and risk scan; explicitly report unmeasured capabilities.
- **Evaluate:** selected scope-specific machine/semantic checks with qualified instruments and evidence.
- **Assure:** consequence-appropriate independent paths, stronger controls, failure injection, consumer validation and external receipts where justified.

These are work-depth choices, not automatic maturity labels or permission upgrades. A small useful dossier is preferable to an unfilled framework. Expand only when a new obligation, unknown, risk or consumer need justifies it.
