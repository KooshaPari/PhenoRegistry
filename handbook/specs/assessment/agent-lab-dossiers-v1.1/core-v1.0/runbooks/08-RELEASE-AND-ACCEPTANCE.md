# Assessment release and acceptance

Resolve the actual subject S, report R and delivered artifact/BOM. R may contain observations about S; do not claim the report commit was itself tested unless it was. Gate membership, evaluator, catalog and scope are frozen for this assessment. New urgent evidence can stop the dependent release even when a prior score was high.

Validate records and exact evidence bytes; independently verify observations and permission claims appropriate to consequence. Confirm no hidden failed jobs, skipped required checks, stale results, conflicting effective leaves, unsupported waivers or unresolved mandatory applicability. Review true installed/consumer behavior and delivery proof separately from build success.

The reference summarizer's exit zero means valid analysis. Inspect individual mandatory gates and current evidence; a passing gate still does not grant publish/merge/deploy authority. Include residual risks, scope and registration state. Produce a report from owner-held evidence rather than treating the report as the sole record.

At package distribution time, check all declared files and hashes, run tests on extracted bytes and retain the validation scope. A SHA-256 manifest detects differences relative to its source; it is not an authenticated attestation without an actual trust/signature path.
