# Adoption work breakdown

The machine-readable `integration/adoption-work-items.json` contains bounded work packages with acceptance and stop rules. These are proposed tasks, not executed portfolio changes. Use them in an existing work owner; do not create another management repository.

## Sequence

First verify this kit locally and select a real small slice. Recover historical rubrics in parallel. Bind actual mandate, intent and subject; qualify the relevant grader; collect real evidence; execute one authorized repair or discriminating experiment; verify separately; checkpoint for a fresh agent; reconcile an optional registry outbox.

Next exercise a CLI/library, a rendered UI, and a cross-repository service or agent journey. These are distinct product forms chosen to challenge applicability and evidence semantics, not a requirement to finish three products before any useful work.

Then import and adjudicate historical criteria, activate high-value adapters and add incremental scheduling. Add formal policy enforcement, cryptographic receipts, stronger isolation or live graphs only to resolve observed risks or bottlenecks. Every infrastructure task names its consumer, cost cap and how work continues without it.

## Definition of accepted bootstrap

A genuine failing outcome is detected at an exact subject snapshot. A valid witness is accepted and a plausible false pass rejected. The correct next action is chosen and owned. An authorized bounded change or experiment produces a result. A separate verification path judges the effect. The record identifies S, R and actual or pending L honestly. A new session continues using preserved learning. Product versus measurement/scope/policy changes remain distinguishable.

The packaged toy verifies only a small deterministic portion of this sequence. Full agent resumption, real repository adoption and external integration remain tasks for the actual permitted environment, not claimed completed by producing this ZIP.
