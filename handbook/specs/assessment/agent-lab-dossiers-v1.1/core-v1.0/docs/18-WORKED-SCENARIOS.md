# Worked scenarios and interpretation

## Executed example: restoration false success

`examples/executed-toy-loop/` contains actual generated evidence from the bundled toy. The before implementation returns success text but fails to restore two records and fails to reject a corrupt backup. The after implementation passes both bounded checks. The same evaluator qualifies a valid witness and rejects the no-op. Both are EXAMPLE records and have distinct actual implementation-variant digests. No real product MVP is asserted.

Run the demo into a new scratch directory to regenerate observations. Run the reference summarizer on before and after. Inspect raw files, results, qualification and measurement bindings rather than only `demo-summary.json`.

## Illustrative scenario: agent-created library

An agent creates a shared parsing library under an accepted decomposition mandate. No human named it. Evaluate its parent capability, actual consumers and alternative placement. Run a separate consumer against its distributed artifact. If it has no useful consumer yet, label utility as hypothetical and choose a bounded experiment. Do not require a web app or human-authored idea.

## Illustrative scenario: polished UI with no functioning backend

Screenshots look finished and automated contrast checks pass. The actual submit operation changes no durable state. Record visual observations separately; core-journey and integration gates fail. Product verification cannot be purchased with polish points. Accessibility conformance remains limited to the evidence actually obtained.

## Illustrative scenario: missing deployment credential

Local code and integration tests pass, but a required hosted deployment cannot be authorized. Mark the deployment action BLOCKED_AUTHORITY in operational narrative and execution BLOCKED / verdict UNKNOWN in result records. Continue permitted local or independent work. Do not mark the product itself broken merely because the credential is missing, and do not call publication verified.

## Illustrative scenario: agents thrash on a wrong test

Repeated candidates satisfy the stated behavior but are rejected because the grader expects one incidental filename. A valid non-identical witness exposes the oracle defect. Create an evaluator amendment and new epoch, retain the old evidence, and remeasure. Score improvement from the corrected evaluator is not product improvement.

## Illustrative scenario: many components, broken integrated product

Individual repositories pass their local suites. The pinned product BOM fails because producer and consumer contracts disagree. Open a cross-owner integration finding with an actual owner, reproduce the consumer journey and decide whether to repair the boundary or merge components. More local checklist entries do not resolve the integration failure.

## Illustrative scenario: excellent engineering, no value evidence

An agent-originated tool has strong implementation and operations evidence but no observed consumer benefit. Do not call it useless solely from missing data. Compare a real internal consumer experiment, narrower scope, upstream reuse, pause and no action. An accepted experiment is legitimate; a high engineering score alone is not justification for indefinite investment.
