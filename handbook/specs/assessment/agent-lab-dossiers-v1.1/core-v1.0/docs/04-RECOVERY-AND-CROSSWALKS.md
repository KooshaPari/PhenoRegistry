# Recover existing templates without losing lineage

This package does not replace the local recovery agents. It gives their output a common import contract. Historical recovery can run while a bounded current assessment proceeds.

## Collection

Within the actual permitted devices and repositories, enumerate known audit/scorecard/rubric/template files, generators, scripts, workflow definitions, completed reports, issue templates and abandoned drafts. Include authorized branch/tag/history views, current worktrees and uncommitted variants. Do not reset a worktree, run garbage collection, delete duplicate-looking files or normalize history during discovery. Record inaccessible devices, shallow history, missing branches, failed commands and source-index limitations.

For each item record device/repository, exact path, commit/blob or content digest, observed branch/worktree, times, role, lineage and collection scope. A report is not necessarily the template that produced it. A filename containing scorecard may identify inventory heuristics rather than a quality rubric. Raw sensitive prompts and credentials must stay in the authorized evidence store.

## Normalization

Extract stable native IDs, predicates, applicability, measurement method, evidence requirement, scoring rule, gate semantics, status model and version. Match by meaning and scope rather than title alone. Classify relationships as EQUIVALENT, NARROWER, BROADER, OVERLAPS, CONFLICTS or SUPERSEDES. Shared terminology is not proof of equivalent evidence standards.

For each recovered item choose ADOPT, SPLIT, MERGE, ADAPT, REJECT or HISTORICAL_ONLY. Preserve the original and a reversible crosswalk. Retain rejected entries and contradictions so a later worker can explain the decision. Do not silently change inherited accepted assurance floors.

## Acceptance and destination

A new canonical catalog requires an explicit accepted decision in the actual schema/catalog owner. This handoff neither creates a new repository nor migrates authority. Keep tool source in its tool repository; subject assessments belong to subjects; registry data belongs to the deployment/registry owner. Generated navigation is a projection.

## Census output

Report source artifacts, versions, original IDs, candidate predicates, equivalence groups, executable adapters, qualified instruments and evaluated instances separately. Missing historical coverage must not be inferred from a small sample. The earlier 88- and 96-pillar observations are retained examples of prior inspection, not the full census and not a current score.

## External frameworks

Retain source title, URI, version, native ID when actually retrieved, retrieval date, rights, exact adaptation and mapping strength. Do not invent ASVS, ISO or other native control IDs. A framework landing page supports a related-reading mapping, not an exact compliance crosswalk. License-restricted full text is not redistributed. A standards update creates a candidate migration rather than silently rescoring historical results.
