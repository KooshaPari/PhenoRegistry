# Semantic review without ungrounded scores

Use semantic review when the predicate requires interpretation: intent coherence, architecture tradeoffs, plan quality, research applicability, copy, visual craft and some user-experience questions. Do not replace a readily executable behavioral check with a model's opinion.

## Review packet

Supply the exact predicate, accepted scope and non-goals, relevant source/artifact version, evidence anchors, contextual constraints, mode of authorship and actual decision authority. Ask for a concise rationale, supporting observations, serious counterevidence, alternative explanations, missing evidence and the smallest next test. Do not request private chain-of-thought transcripts.

## Anchors

For a binary gate, define observable supporting and refuting conditions. For ordinal exploration, describe every level with behaviors rather than adjectives. Keep ordinal ratings separate from numerical interval assumptions. Two ratings of 3 do not necessarily sum to one rating of 6. Proposed anchors are themselves revisable artifacts and must be frozen within the assignment epoch.

## Review output

Use PASS only when the evidence supports the scoped predicate at the required assurance level. Use FAIL for a supported violation. Use UNKNOWN for missing evidence, inadequate expertise or an unresolved measurement method. Use CONTESTED when credible interpretations conflict. A high confidence number without calibration is not proof. Record source/model/procedure identity, not a fictional guarantee of repeatability.

## Calibration and disagreement

Keep a versioned set of valid, invalid and ambiguous cases. Measure how each reviewer handles them and retain disagreement. Change case order and remove prior aggregate grades when anchoring bias is material. Independent evidence derivations are stronger than multiple agents copying the same README. When a mandatory claim requires knowledgeable human or specialist evaluation, do not claim agent agreement supplies it; expose the exact gap while continuing unrelated authorized work.

## Counterexample discipline

For every high-impact positive conclusion, consider plausible alternatives including a wrong objective, a narrower useful scope, a broken measurement and no action. State what observation would distinguish them. This is an operational falsification discipline, not a demand to pretend every alternative is equally plausible or to produce a formal proof where evidence cannot support one.

## Accessibility and product value

Automated accessibility checks cover only parts of an evaluation; W3C's guidance does not support full conformance from tools alone [W3C-EVALUATION]. Synthetic users and agent consumers must be labeled. Real agent-consumer execution can establish internal workflow value; it is not external human market demand.
