# Architecture decision records for this handoff

These are proposed design decisions, not enacted authority migrations.

## ADR-001 — Portable protocol before platform

Choose owner-held records and existing harnesses. Alternative: block on live AgilePlus/Tracera. Reason: the protocol must enable useful work now and later feed qualified adapters. Consequence: early coordination is procedural and only selected integrity checks are executable. Revisit when real transport integration measurably removes a bottleneck.

## ADR-002 — One model, multiple projections

Separate inventory, criteria, observations, findings, decisions and maturity. Alternative: one giant spreadsheet score. Reason: a declaration, result and investment decision have different truth conditions. Consequence: more explicit record types, less accidental authority promotion. Revisit schema complexity when it obstructs a real bounded loop.

## ADR-003 — Candidate catalog plus scoped activation

Ship a broad original bank with explicit procedure-only status. Alternative: call all entries mandatory/automated or postpone until historical recovery is complete. Reason: coverage navigation is useful while qualification and recovery proceed. Consequence: real assignments must resolve applicability, overlaps and instruments.

## ADR-004 — Agents may amend the grader

Freeze each epoch but allow qualified, attributable amendments. Alternatives: unchangeable human grader or builder-controlled moving target. Reason: agent-defined tasks can be wrong; correction must not look like implementation progress. Consequence: retain old baselines and classify deltas.

## ADR-005 — Finite conditional trust boundary

Use actual authority, enforced environment boundaries and independent evidence where needed. Alternative: infinite meta-graders or the claim that every agent agreement is ground truth. Reason: all components remain fallible. Consequence: describe conditional assurance and unresolved external evidence honestly.

## ADR-006 — No universal lifecycle score

Keep engineering, assurance, delivery and value separate. Alternative: automatically retire low-scoring products or fund high-scoring ones. Reason: they answer different questions. Consequence: strategic decisions compare hypotheses and actual outcome evidence under delegated resource authority.

## ADR-007 — Standard-library reference kernel

Implement strict input parsing, the shipped schema subset and deterministic reductions without runtime dependencies. Alternative: make the bootstrap depend on a new service stack. Consequence: the kernel is deliberately bounded and not a universal JSON Schema or product execution engine. Independent full-schema checks are development validation, not runtime requirements.

## ADR-008 — Exact byte hashes at exchange boundaries

Hash actual artifacts and assignment files; label the helper's Python JSON representation separately. Alternative: claim undocumented cross-language canonicalization or signatures. Consequence: any byte change creates a new identity, and independent authenticity remains a separate concern.
