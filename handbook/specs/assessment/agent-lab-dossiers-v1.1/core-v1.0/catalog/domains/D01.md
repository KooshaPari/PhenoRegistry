# D01 — Intent and value

Status: authored candidate predicates. No product results or automatically qualified adapters are implied. Exact-duplicate checks do not establish semantic uniqueness; resolve cross-cutting overlaps when weighting an assignment.

## D01-P01 — Mandate and delegated authority
Applicability trigger: all subjects.
Method: **SEMANTIC**. Resolve actual host permissions and parent mandates; compare each selected action with explicit scope and counterexamples outside that scope.

- **PEP-01-01-01** — The current work has an identifiable source of delegated authority.
- **PEP-01-01-02** — The mandate distinguishes permitted observation from permitted mutation.
- **PEP-01-01-03** — Resource limits remain cumulative across replacement agent sessions.
- **PEP-01-01-04** — Subdelegation does not enlarge the delegating actor's actual permissions.
- **PEP-01-01-05** — Reserved sponsor decisions are distinguishable from routine agent decisions.
- **PEP-01-01-06** — Expiration or revocation of authority has an actionable stop condition.
- **PEP-01-01-07** — Conflicting mandates have an explicit precedence resolution.
- **PEP-01-01-08** — External effects have permissions separate from local experimentation.
- **PEP-01-01-09** — The permitted subject set excludes unrelated repositories and devices.
- **PEP-01-01-10** — An agent can proceed with independent authorized work when another action is blocked.

## D01-P02 — Beneficiary and problem hypothesis
Applicability trigger: all subjects.
Method: **SEMANTIC**. Trace the problem to observations or explicitly hypothetical consumers; compare the proposed outcome against current behavior and the no-build alternative.

- **PEP-01-02-01** — The proposed beneficiary is distinguishable from the builder role.
- **PEP-01-02-02** — The beneficiary's current problem is stated as observable friction.
- **PEP-01-02-03** — Evidence status distinguishes a hypothesized problem from an observed problem.
- **PEP-01-02-04** — The frequency of the problem has a declared observation basis.
- **PEP-01-02-05** — The consequence of leaving the problem unsolved is articulated.
- **PEP-01-02-06** — The expected beneficiary context matches the intended deployment context.
- **PEP-01-02-07** — Conflicting beneficiary needs remain visible rather than averaged away.
- **PEP-01-02-08** — An internal agent consumer is identified by a real workflow or a labeled proposed workflow.
- **PEP-01-02-09** — The problem statement does not assume the proposed implementation is necessary.
- **PEP-01-02-10** — A refutation condition exists for the problem hypothesis.

## D01-P03 — Value and outcome contracts
Applicability trigger: all subjects.
Method: **SEMANTIC**. Create a before/after outcome contract with baseline, unit, observation window and disconfirmation; distinguish evidence collection from benefit.

- **PEP-01-03-01** — The intended improvement is expressed in beneficiary-observable terms.
- **PEP-01-03-02** — The baseline includes the existing workaround where one exists.
- **PEP-01-03-03** — Success thresholds have a stated rationale rather than arbitrary round numbers.
- **PEP-01-03-04** — Outcome measurements have explicit observation windows.
- **PEP-01-03-05** — Benefits and costs use comparable scope and units.
- **PEP-01-03-06** — A technically passing result can still be classified as value-unproven.
- **PEP-01-03-07** — Negative consequences of the proposed improvement are considered.
- **PEP-01-03-08** — The outcome contract identifies conditions under which improvement would not generalize.
- **PEP-01-03-09** — An outcome owner can obtain the required observation without relying on builder testimony.
- **PEP-01-03-10** — The outcome hypothesis names a practical discriminating experiment.

## D01-P04 — Agent-derived intent and repository genesis
Applicability trigger: subjects created or materially reshaped by agents.
Method: **SEMANTIC**. Reconstruct lineage without inventing history; compare repository separation to a module, package, existing owner, upstream reuse and no build.

- **PEP-01-04-01** — Intent authorship is recorded separately from intent acceptance.
- **PEP-01-04-02** — Derived intent links to its parent capability or mandate.
- **PEP-01-04-03** — An absent historical origin is reported as a provenance gap.
- **PEP-01-04-04** — The repository boundary has an explicit consumer-facing responsibility.
- **PEP-01-04-05** — Separate release cadence is justified when used to motivate a new repository.
- **PEP-01-04-06** — Cross-boundary coupling costs are included in the decomposition decision.
- **PEP-01-04-07** — An existing-owner alternative was evaluated before creating duplicate authority.
- **PEP-01-04-08** — The repository has an absorption or reversal trigger.
- **PEP-01-04-09** — The proposed repository name is not used as evidence of product necessity.
- **PEP-01-04-10** — Accepted current intent is not falsely attributed to the original creation event.

## D01-P05 — Alternatives and non-goals
Applicability trigger: all subjects.
Method: **SEMANTIC**. Compare feasible competing approaches against the same outcome and constraints; preserve rejection reasons and counterevidence.

- **PEP-01-05-01** — The no-action alternative is evaluated on the same outcome as building.
- **PEP-01-05-02** — An upstream or off-the-shelf alternative is considered when relevant.
- **PEP-01-05-03** — A smaller scope alternative is considered before adding infrastructure.
- **PEP-01-05-04** — Non-goals exclude concrete tempting work rather than vague categories.
- **PEP-01-05-05** — Rejected alternatives retain the evidence supporting rejection.
- **PEP-01-05-06** — The chosen approach has identifiable conditions under which another alternative wins.
- **PEP-01-05-07** — Tradeoffs include ongoing maintenance rather than construction alone.
- **PEP-01-05-08** — Constraints are distinguished from inherited preferences.
- **PEP-01-05-09** — New evidence can reopen a previously rejected alternative.
- **PEP-01-05-10** — A brainstorm is not promoted to a mandatory requirement without a decision.

## D01-P06 — Feedback and intent amendments
Applicability trigger: subjects receiving sponsor, consumer or agent feedback.
Method: **SEMANTIC**. Classify feedback, preserve its source, apply actual authority, and compare prior and amended intent without rewriting observed facts.

- **PEP-01-06-01** — Feedback is classified as instruction, preference, observation, question, brainstorm or override.
- **PEP-01-06-02** — The original feedback and its operational interpretation are distinguishable.
- **PEP-01-06-03** — A preference change does not retroactively alter historical test observations.
- **PEP-01-06-04** — Binding scope changes identify the assignment epochs they invalidate.
- **PEP-01-06-05** — Ambiguous reversible ideas can become bounded experiments without fabricated certainty.
- **PEP-01-06-06** — Ambiguous authority for irreversible actions remains unresolved.
- **PEP-01-06-07** — Conflicting feedback is reconciled using explicit priority and evidence.
- **PEP-01-06-08** — A major intent change preserves the previous accepted version.
- **PEP-01-06-09** — Amendments identify consumers affected by the change.
- **PEP-01-06-10** — The amendment record separates changed goals from newly learned facts.
