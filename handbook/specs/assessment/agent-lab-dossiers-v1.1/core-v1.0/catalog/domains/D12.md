# D12 — Performance and resource use

Status: authored candidate predicates. No product results or automatically qualified adapters are implied. Exact-duplicate checks do not establish semantic uniqueness; resolve cross-cutting overlaps when weighting an assignment.

## D12-P01 — Workload definition and measurement integrity
Applicability trigger: subjects making performance or resource claims.
Method: **STRUCTURAL**. Inspect workload, hardware, toolchain, clock and sampling definitions; replay the measurement from retained raw observations.

- **PEP-12-01-01** — The workload represents the claimed user or agent scenario.
- **PEP-12-01-02** — Input size and distribution are specified.
- **PEP-12-01-03** — Concurrency means active work rather than merely open sessions.
- **PEP-12-01-04** — Warm-cache and cold-cache conditions are distinguished.
- **PEP-12-01-05** — Hardware and relevant power or scheduling settings are recorded.
- **PEP-12-01-06** — Measurement units and clock sources are explicit.
- **PEP-12-01-07** — Percentiles are computed from a retained observation set.
- **PEP-12-01-08** — Timed-out or failed operations remain in the reported workload outcome.
- **PEP-12-01-09** — The benchmark identifies the exact artifact and configuration.
- **PEP-12-01-10** — A result from one environment is not silently promoted to another environment's guarantee.

## D12-P02 — Latency and responsiveness
Applicability trigger: latency-sensitive products.
Method: **DYNAMIC**. Measure end-to-end and stage latency under the selected workload, including cold start and accepted contention conditions.

- **PEP-12-02-01** — End-to-end latency includes all user-visible required stages.
- **PEP-12-02-02** — Tail latency is reported when it matters to the accepted task.
- **PEP-12-02-03** — Cold-start latency is measured separately from steady state.
- **PEP-12-02-04** — Queue waiting time is included or explicitly separated.
- **PEP-12-02-05** — Cancellation latency meets the declared response budget.
- **PEP-12-02-06** — Input-to-feedback latency is measured for real interactive paths.
- **PEP-12-02-07** — A latency optimization preserves required correctness.
- **PEP-12-02-08** — Timeout behavior respects the total request deadline.
- **PEP-12-02-09** — Slow dependency behavior is included in the latency scenario.
- **PEP-12-02-10** — The measured target uses the selected platform and display or transport path.

## D12-P03 — Throughput, capacity and backpressure
Applicability trigger: systems serving concurrent work.
Method: **DYNAMIC**. Sweep bounded load through the operating range; observe completed useful work, queue growth, fairness and saturation behavior.

- **PEP-12-03-01** — Throughput counts completed valid operations rather than attempted requests.
- **PEP-12-03-02** — Capacity is measured at the accepted latency and error bounds.
- **PEP-12-03-03** — Queue growth remains bounded under sustained overload.
- **PEP-12-03-04** — Backpressure is observable to the submitting client.
- **PEP-12-03-05** — Admission control prevents work beyond the configured capacity envelope.
- **PEP-12-03-06** — Concurrent projects receive the declared fairness behavior.
- **PEP-12-03-07** — Increasing concurrency does not silently drop required work.
- **PEP-12-03-08** — Saturation produces a diagnosable degraded state.
- **PEP-12-03-09** — Recovery from overload does not require losing accepted durable tasks.
- **PEP-12-03-10** — Burst-load claims identify burst length and recovery conditions.

- **PEP-12-04-01** — Peak memory is measured for the selected workload.

- **PEP-12-04-09** — Resource-saving modes preserve explicitly required behavior.
- **PEP-12-04-10** — Published efficiency claims include the measurement scope and excluded overhead.

## D12-P05 — Mixed-load and multi-device performance
Applicability trigger: products intended for shared hosts, VMs or remote devices.
Method: **DYNAMIC**. Run representative competing CPU, GPU, storage, network and real-time workloads under authorized native or VM isolation.

- **PEP-12-05-01** — Foreground interactive work is included when shared-host operation is promised.
- **PEP-12-05-02** — Audio-sensitive workloads are evaluated for relevant interruption or deadline failures.
- **PEP-12-05-03** — GPU contention is measured under the selected graphics or inference coexistence scenario.
- **PEP-12-05-04** — Storage-heavy background work is included in relevant responsiveness tests.
- **PEP-12-05-05** — Remote network variation is distinguished from local processing latency.
- **PEP-12-05-06** — Cross-device clock uncertainty is accounted for in timing claims.
- **PEP-12-05-07** — VM or sandbox overhead is measured in the actual intended configuration.
- **PEP-12-05-08** — Dynamic resource allocation does not violate the foreground reservation policy.
- **PEP-12-05-09** — Quality degradation is measured alongside latency improvements.
- **PEP-12-05-10** — The test records the actual concurrently active workloads rather than a nominal fleet size.

## D12-P06 — Performance regression and economic efficiency
Applicability trigger: products with performance baselines or cost targets.
Method: **DYNAMIC**. Compare matched baseline and candidate runs; include setup, verification, retries and useful outcomes in efficiency analysis.

- **PEP-12-06-01** — Performance comparisons use matched workload definitions.
- **PEP-12-06-02** — A faster result is rejected when it fails the required correctness gate.
- **PEP-12-06-03** — Resource-cost reports include failed attempts and retries.
- **PEP-12-06-04** — Cache-related savings identify hit rate and cache population assumptions.
- **PEP-12-06-05** — An optimization's effect exceeds or acknowledges measurement variability.
- **PEP-12-06-06** — Regression thresholds have an accepted product rationale.
- **PEP-12-06-07** — A baseline update preserves the old measurement and environment identity.
- **PEP-12-06-08** — Cost per outcome uses accepted outcomes rather than rubric points.
- **PEP-12-06-09** — Parallel execution reports both wall-clock savings and total resource use.
- **PEP-12-06-10** — Performance claims are refreshed when a material environment or dependency changes.
