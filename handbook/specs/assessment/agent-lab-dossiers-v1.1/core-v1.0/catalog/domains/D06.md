# D06 — Test and assurance quality

Status: authored candidate predicates. No product results or automatically qualified adapters are implied. Exact-duplicate checks do not establish semantic uniqueness; resolve cross-cutting overlaps when weighting an assignment.

## D06-P01 — Test inventory and behavioral coverage
Applicability trigger: subjects with executable behavior.
Method: **STRUCTURAL**. Map tests to obligations and actual selected execution; distinguish source coverage, assertion coverage and consumer behavior.

- **PEP-06-01-01** — The test inventory identifies which accepted obligations each suite exercises.
- **PEP-06-01-02** — Required test selection includes the intended packages and platforms.
- **PEP-06-01-03** — Source coverage is reported separately from behavioral coverage.
- **PEP-06-01-04** — Tests contain assertions about meaningful outcomes.
- **PEP-06-01-05** — Skipped tests are visible in the assessment denominator.
- **PEP-06-01-06** — A zero-test run cannot satisfy a required test obligation.
- **PEP-06-01-07** — Uncovered mandatory behavior remains a blocker despite aggregate coverage.
- **PEP-06-01-08** — Test-only helper behavior is not counted as product behavior coverage.
- **PEP-06-01-09** — Coverage reports identify the exact subject and instrument revision.
- **PEP-06-01-10** — Independent coverage floors are not combined to hide a failing family.

## D06-P02 — Oracle and grader qualification
Applicability trigger: all evaluation instruments.
Method: **DYNAMIC**. Run a valid witness and targeted invalid witnesses through the exact evaluator; preserve false-positive and false-negative observations.

- **PEP-06-02-01** — The grader accepts a valid solution that differs from its reference implementation.
- **PEP-06-02-02** — The grader rejects an empty or no-op implementation for nonempty behavior.
- **PEP-06-02-03** — A forced-success exit status cannot override failed outcome assertions.
- **PEP-06-02-04** — A corrupted expected artifact is detected.
- **PEP-06-02-05** — The grader distinguishes a product failure from a runner failure.
- **PEP-06-02-06** — A wrong subject revision is rejected as mismatched evidence.
- **PEP-06-02-07** — The oracle's expected result has a justification outside the candidate output alone.
- **PEP-06-02-08** — Grader inputs cannot be silently rewritten by the implementation worker.
- **PEP-06-02-09** — Known grader limitations constrain the claims it may support.
- **PEP-06-02-10** — A grader update has its own version and qualification record.

## D06-P03 — Integration and end-to-end assurance
Applicability trigger: products with integrations or end-to-end workflows.
Method: **DYNAMIC**. Execute real supported boundary paths in a disposable composition and inspect durable effects using an independent observer.

- **PEP-06-03-01** — The integration suite exercises the actual protocol boundary.
- **PEP-06-03-02** — Mock-only tests are labeled separately from real integration tests.
- **PEP-06-03-03** — External side effects are verified rather than inferred from a success message.
- **PEP-06-03-04** — The suite exercises permission-denied responses from a real boundary.

- **PEP-06-03-08** — The end-to-end test starts without privileged developer leftovers.
- **PEP-06-03-09** — Failure recovery is included in the required journey suite.

## D06-P04 — Property, mutation and fuzz assurance
Applicability trigger: subjects whose risk justifies generative or adversarial testing.
Method: **DYNAMIC**. Generate inputs under justified invariants, retain seeds and shrinking results, and measure whether meaningful code mutations are detected.

- **PEP-06-04-01** — Property tests state independently justified invariants.
- **PEP-06-04-02** — Generated input ranges include relevant boundaries.
- **PEP-06-04-03** — Failing generated cases retain reproducible seeds or minimized inputs.
- **PEP-06-04-04** — Mutation results distinguish killed, surviving and unexercised mutants.
- **PEP-06-04-05** — Equivalent or invalid mutants have reviewed exclusion reasons.
- **PEP-06-04-06** — Fuzz campaigns use an explicit resource and termination budget.
- **PEP-06-04-07** — Crashes are triaged separately from intended validation failures.
- **PEP-06-04-08** — A discovered counterexample becomes a retained regression case.
- **PEP-06-04-09** — Metamorphic relations are justified for the actual domain.
- **PEP-06-04-10** — Differential comparisons identify the reference and its known limitations.

## D06-P05 — Test isolation and repeatability
Applicability trigger: subjects with repeatable tests.
Method: **DYNAMIC**. Repeat and reorder tests in clean environments; deliberately contaminate one trial to verify isolation and reset behavior.

- **PEP-06-05-01** — Tests do not depend on undocumented execution order.
- **PEP-06-05-02** — A fresh trial resets state required for independence.
- **PEP-06-05-03** — Clock-sensitive tests use a controlled or explicitly observed clock.
- **PEP-06-05-04** — Randomness affecting results is recorded.
- **PEP-06-05-05** — A failed test cannot contaminate an unrelated subsequent test.
- **PEP-06-05-06** — Temporary resources are uniquely scoped per trial.
- **PEP-06-05-07** — Parallel test execution preserves declared invariants.
- **PEP-06-05-08** — Flaky outcomes remain visible rather than rerun until hidden.
- **PEP-06-05-09** — A repeated test uses the same artifact and relevant environment inputs.
- **PEP-06-05-10** — Fixture setup failure cannot be reported as a passing product test.

## D06-P06 — Regression and assurance change control
Applicability trigger: subjects with accepted baselines.
Method: **DYNAMIC**. Compare prior and candidate behavior under a frozen baseline; exercise a seeded regression and inspect baseline-update permissions.

- **PEP-06-06-01** — A new capability does not silently remove prior mandatory coverage.
- **PEP-06-06-02** — Accepted behavior has retained regression cases.
- **PEP-06-06-03** — A seeded regression fails the intended gate.
- **PEP-06-06-04** — Test expectation changes are reviewed as evaluator changes when they alter meaning.
- **PEP-06-06-05** — A baseline update preserves the previous baseline identity.
- **PEP-06-06-06** — Regression waivers have scope, owner and expiry.
- **PEP-06-06-07** — Reopened defects are visible in progress reporting.
- **PEP-06-06-08** — Required failures cannot be hidden by changing suite aggregation.
- **PEP-06-06-09** — Release acceptance uses the actual integrated artifact rather than only a premerge candidate.
- **PEP-06-06-10** — A measurement defect can be corrected without mislabeling it as product improvement.
