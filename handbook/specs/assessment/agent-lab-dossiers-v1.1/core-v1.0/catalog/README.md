# Catalog contract

The catalog contains **18 domains, 108 pillars and 1,080 authored candidate entries**. Entries express specific outcomes, not a multiplication of one rule over platforms. These counts describe this package, not the user's historical rubric recovery. Semantic overlap remains possible, particularly between product controls and checks of the evaluator itself. Do not advertise the entry count as 1,080 independently qualified controls.

`catalog.json` is the editable machine authority for this release; domain Markdown files are readable projections. If changing JSON, regenerate the projections and release a new catalog revision. Never edit generated tables as a second authority.

Every entry has applicability, modality, a procedure, evidence needs, positive/negative control design, invalidators, activation requirements and provenance. `PROCEDURE_ONLY` and `UNQUALIFIED` mean exactly that: the package has not run these product checks. Bind the method to a real subject and qualify its instrument before using a result for a gate. Semantic procedures are usable by agents now, but missing anchors or evidence remain UNKNOWN.

A product assessment selects a bounded profile and creates scoped instances. Instances have obligation keys; overlapping catalog entries must share one obligation or be explicitly justified as independent. The reference kernel rejects repeated obligation keys rather than multiplying their credit. A broader profile is not automatically a stricter or better product. Full-catalog discovery may run in parallel with a small implementation slice.

Use `profiles/*.json` as navigation aids, not authority or automatic non-applicability. A missing capability declaration leaves related applicability unresolved. Add genuinely absent criteria with new stable IDs and provenance; retain rejected and superseded entries. Historical recovery uses `docs/04-RECOVERY-AND-CROSSWALKS.md`.
